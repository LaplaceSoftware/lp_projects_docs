## Changes

- Account managers now receive an email as soon as a client updates the status of one of their orders (PR 625).
- Those notification emails now use wording specific to each event — RFQ submitted, RFQ updated, purchase order submitted, wishlist shared — instead of one generic message for everything (PR 627).
- A client company can now be assigned more than one account manager, so follow-up coverage isn't limited to a single person (PR 628).
- Fixed an issue where simply refreshing the client portal page could incorrectly trigger an "online" notification (PR 635).
- Fixed a permissions gap that could prevent certain users from uploading attachments (PR 637).
- The system now blocks adding new items to an order that has already been cancelled or confirmed, preventing orders from ending up in an inconsistent state (PR 639).
- Removed a leftover internal configuration page that shouldn't have been included in the demo/setup data (PR 644).
