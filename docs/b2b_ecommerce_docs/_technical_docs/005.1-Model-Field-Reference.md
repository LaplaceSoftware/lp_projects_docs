# 005.1 — Model & Field Reference

Field-level companion to [005 — Domain Model](005-Domain-Model.md). Where 005 stays high-level
(models that matter, how they relate), this document is the exhaustive reference: every model
in the `ecommerce` addon and every field it defines, with type, relation/selection values, label
and description.

**Scope rule:**

- **Custom models** (`_name` starting with `ecommerce.*`) — every field is listed.
- **Extended standard Odoo models** (`_inherit` on `res.users`, `sale.order`, `product.template`,
  etc.) — only fields this module actually adds or redefines are listed. Native Odoo fields not
  touched by this module (e.g. `sale.order.state`, `product.template.list_price`) are out of
  scope; consult standard Odoo documentation for those.
- Source: `addons_lp_ecommerce/ecommerce/models/*.py`, live scan.

### `ecommerce.product.request.line`

**File:** `models/product_request_line.py` · **Inherits:** `mail.thread`, `mail.activity.mixin`
Client request for a product not currently in the catalog, tied to a sale order, progressing until an account manager sources/creates the product or marks it not found.

| Field | Type | Relation / Selection | Label | Description | Notes |
|---|---|---|---|---|---|
| `name` | Char | — | Name | Requested product's name/title | `tracking=True` |
| `description` | Char | — | Description | Free-text description | `tracking=True` |
| `requested_qty` | Float | — | Quantity | Quantity requested | `required=True`, `default=1.0` |
| `state` | Selection | see table below | State | Fulfillment workflow status | `default='submitted'`, `tracking=True` |
| `request_date` | Date | — | Request Date | Date the request was submitted | `default=today` |
| `in_progress_date` | Date | — | In Progress Date | Date moved to in-progress | no auto-stamping logic in this file |
| `added_date` | Date | — | Added Date | Date the product was added | no auto-stamping logic in this file |
| `not_found_date` | Date | — | Not Found Date | Date marked not-found | no auto-stamping logic in this file |
| `is_product_created` | Boolean | — | Is Product Created | Whether a product record was created for this request | `default=False` |
| `reference_url` | Char | — | Reference URL | Client-supplied reference link | — |
| `is_ecommerce_portal` | Boolean | — | Is Ecommerce Portal | Flags request as created via the portal | set by `api_create_product_request_line` |
| `created_product_id` | Many2one | `product.product` | Created Product | Catalog product created/matched to fulfill the request | cleared automatically on transition to `not_found` |
| `sale_order_id` | Many2one | `sale.order` | Sale Order | Order this request is attached to | `ondelete='cascade'` |
| `portal_company_partner_id` | Many2one | `res.partner` | Customer | Client company that made the request | — |
| `portal_create_uid` | Many2one | `res.users` | Portal Create User | User who submitted the request | `index=True`, `readonly=True` |
| `portal_write_uid` | Many2one | `res.users` | Portal Write User | Last user who updated the request | `readonly=True`; not actually populated anywhere in this file |
| `added_order_line_id` | Many2one | `sale.order.line` | Added Order Line | Order line auto-created once the product is added | `tracking=True`; domain restricted to lines of `sale_order_id` |

**`state` values:**

| Value | Label | Meaning |
|---|---|---|
| `submitted` | Request Submitted | Awaiting account-manager review |
| `in_progress` | In Progress | Account manager sourcing/investigating |
| `product_added` | Product Added | Product linked/created, order line auto-generated |
| `not_found` | Product Not Found | Could not be sourced; closed, no product/line |

Auto-order-line logic: `_auto_create_order_line()` creates a `sale.order.line`
(`product_uom_qty = requested_qty`, `manual=True`) once `state='product_added'` with both
`created_product_id` and `sale_order_id` set (skipped if the order is already confirmed);
`_delete_old_order_line()` removes the stale line and posts a chatter note if the linked product
changes. `sale_order_id.new_product_requests_count` counts lines still `submitted`.

**Notable behaviour:**
- `_compute_im_status` treats stored "online"/"away" presence as stale (reports offline) once
  `last_poll` exceeds the disconnection timer — worked around because Odoo.sh's gateway owns the
  websocket and the native close handler never fires (see
  [012 — Real-Time and Messaging](012-Realtime-and-Messaging.md)).
- `create()` auto-assigns `base.group_portal` (portal users) or
  `ecommerce_group_account_manager` + sales/account manager groups (account managers) based on
  `is_ecommerce_portal`/`is_account_manager` context flags.
- `write()` revokes all active sessions when `activate` or `portal_activate` flips False→True→False.
- OTP flow: `generate_otp()` (4-digit, expiry from `ecommerce.otp_expiry_minutes` system parameter,
  default 5 min), `send_otp_mail()`, `verify_opt()`, `change_password_with_otp()`.
- QR/invitation URLs resolve `shop_portal_url` from the account manager's system parameter or the
  portal user's own company partner.

| Value | Label |
|---|---|

| `delivered` | Delivered |
| `cancel` | Cancelled |

**`portal_order_planning_state` values:** `late` / `on_time` / `upcoming`. Closed states
(`rfq_submitted` → `delivered`, and `rejected`) always report `on_time` regardless of date; open
states compare `portal_planned_order_date` to today.

**State-transition logic** (see [008 — Order Lifecycle](008-Order-Lifecycle.md) for the full
picture): `api_update_order()` is the central entry point — validates the target state, blocks
leaving `draft`/`rejected`/`cancel` with no order lines, routes `quotation_submitted` through
`action_quotation_send()` (PDF + email + resets review flags) and `in_progress` through
`action_confirm()`, otherwise maps `portal_state → native state` via a static table
(`draft/pending_approval/rfq_submitted/rfq_updated → draft`, `rejected → cancel`,
`quotation_submitted/po_submitted → sent`, `delivered → sale`, `cancel → cancel`). Toggling
`portal_visible` True→False calls `action_done_reply()`; False→True raises an
`ecommerce.notification` and notifies the account manager (wishlist-share flow). Only the
order's `create_uid` may `unlink()` it; order lines are frozen once `state='sale'` or
`portal_state='cancel'`.
